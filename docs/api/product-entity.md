# Local Entity — Product

> The practical exam does not require local persistence for products. Product data is stored in memory by the Express API and is reset when the server restarts.

- **Store:** N/A — in-memory storage in the Express API
- **Table/collection:** N/A
- **Schema version introduced:** N/A

---

## Purpose

The `Product` model represents an item in the product catalog.

Products are exposed by the Express REST API and consumed by the Ionic React application.

The server starts with eight products loaded from:

```text
server/data/products.json
```

After the server starts, the application works with an in-memory product collection.

---

## Fields

| Column | Type | Null | Notes |
|--------|------|------|-------|
| `id` | number | No | Unique incremental identifier generated by the server |
| `name` | string | No | Required non-empty product name, maximum 60 characters |
| `price` | number | No | Product price, must be greater than 0 |
| `category` | string | No | Must be `Bebidas`, `Snacks`, `Aseo` or `Hogar` |
| `stock` | integer | No | Available quantity, must be greater than or equal to 0 |

---

## Domain model

The Ionic application represents a product with a domain type similar to:

```ts
export type ProductCategory =
  | 'Bebidas'
  | 'Snacks'
  | 'Aseo'
  | 'Hogar';

export type Product = {
  id: number;
  name: string;
  price: number;
  category: ProductCategory;
  stock: number;
};
```

The domain model contains the data received from the Express API.

Presentation-specific values such as formatted price and stock labels are derived from the domain model instead of being stored directly.

## Validation rules

The Express API and the Ionic application must apply the same validation rules.

### `name`

The product name:

- Is required.
- Must be a string.
- Cannot be empty or contain only whitespace.
- Has a maximum length of 60 characters.

### `price`

The product price:

- Is required.
- Must be a number.
- Must be greater than 0.

### `category`

The category:

- Is required.
- Must be one of the allowed values.

Allowed categories:

```text
Bebidas
Snacks
Aseo
Hogar
```

### `stock`

The stock:

- Is required.
- Must be an integer.
- Must be greater than or equal to 0.

---

## Presentation mapping

The domain product is transformed for the UI using `toProductView`.

### Formatted price

The product price is formatted using `formatCOP`.

Example:

```text
1250000 → $ 1.250.000
```

The formatted value is used only for presentation.

The original numeric value remains in the domain object.

---

## Stock label

The product stock is converted into a user-friendly label.

| Stock condition | Label |
|-----------------|-------|
| `stock === 0` | `Agotado` |
| `stock < 5` | `Pocas unidades` |
| `stock >= 5` | `Disponible` |

Examples:

```text
0 → Agotado
3 → Pocas unidades
10 → Disponible
```

## Persistence

The practical exam uses in-memory persistence on the Express server.

Initial products are loaded from:

```text
server/data/products.json
```

The following operations modify the in-memory product collection:

- Create product.
- Update product.
- Delete product.

A new product receives an incremental identifier.

Example:

```text
Existing highest id: 8
New product id: 9
```

The changes are not permanently stored in a database.

When the Express server restarts, the product collection returns to its initial state.

## Local persistence

Local persistence is not required.

The Ionic application does not use:

- SQLite.
- Room.
- Realm.
- IndexedDB for product persistence.
- A local product database.

The application obtains product information from the Express API.

---

## Sync

- **Synced?** No
- **Conflict policy:** N/A

There is no synchronization process between local and remote storage because no local product database exists.

The Express API is the source used by the application during execution.

---

## Offline behavior

There is no offline product cache.

If the API is unavailable, the application displays an error state.

The product list includes retry behavior so the user can request the data again after connectivity is restored.
